# Бросай и лови

С чердака кидаешь бабушкины тапки, а потом и другой хлам. На грохот сбегается нечисть: её надо успеть тыкнуть. Пойманные живут в загоне и таскают гроши, даже пока игра закрыта. Гроши тратятся на замах, снаряд потяжелее и сам загон.

Движок: **Godot 4.7.2**, GDScript, без .NET. Рендер: GL Compatibility. Веб-экспорт однопоточный, без SharedArrayBuffer и без заголовков cross-origin isolation. Его можно класть на GitHub Pages.

Игра живёт в этой папке и не заменяет ни «Огурчика Чака» в корне, ни «Откроешь дверь?». После деплоя:

- корень: https://dmitriigame.github.io/garlic_games/
- дверь: https://dmitriigame.github.io/garlic_games/door/
- эта игра: https://dmitriigame.github.io/garlic_games/throw/

Рекламы и награды за ролик нет.

## Открыть проект

1. Поставить [Godot 4.7.2](https://godotengine.org/download/archive/4.7.2-stable/) (стандартная сборка, не .NET).
2. Godot → Import → `throw/project.godot`.
3. F5. Окно узкое и вертикальное. На телефоне сцена занимает экран.

Управление: палец или мышь. Пробел бросает так же, как кнопка. `1`–`4` переключают вкладки, `M` глушит звук, `E` открывает правку чисел. Звук стартует после первого касания.

## Как играть

Полоска силы сама ходит вверх-вниз. Зажми «Бросить» и отпусти, когда подпись показывает нужные метры. Тапок летит в тот край, чья дальность уже пройдена: двор, огород, лес, болото, баня, кладбище. На месте выбегает нечисть этого края. Тыкай её, пока не сбежала. Редкая ждёт меньше.

Поимка сразу даёт немного грошей и записывает существо в бестиарий. Повтор той же нечисти увеличивает её доход, но не без конца. В загоне работают самые доходные, пока хватает мест. Остальные ждут в бестиарии.

Гроши капают каждую секунду, пока игра открыта. Когда её закрывают, загон догоняет простой по сохранённому времени, но не дольше `offline_cap_sec` (сейчас 8 часов). Дольше этого они без хозяина ленятся.

Дальность открывает края. Короткий бросок по-прежнему попадает во двор: минимальная дальность не растёт, растёт только прибавка от силы. Поэтому старую нечисть можно добирать и после самовара.

## Откуда числа

Код читает пять файлов. Тексты, цены, редкость и доход правятся там, без скриптов.

| Файл | Что внутри |
| --- | --- |
| `data/balance.json` | Дальность, загон, оффлайн, редкости, скорость полоски. Блок `sim` нужен только расчёту баланса, в игре не используется. |
| `data/biomes.json` | Края: id, имя, дальность открытия, цвет земли, фраза. |
| `data/creatures.json` | Нечисть: край, редкость, вес, фигура, цвет, реплика. |
| `data/items.json` | Снаряды по порядку: цена, множитель дальности, приманка. |
| `data/upgrades.json` | Четыре покупки с эффектом в коде: `throw_power`, `pen_slots`, `pen_income`, `lure`. |

Фигуры нечисти: `blob`, `squat`, `tall`, `horned`, `wispy`. Неизвестная фигура рисуется комком.

Редкость задаёт доход в секунду, секунды на тычок и горсть грошей сразу. Вес в строке нечисти решает, кто выбежит. Цвета краёв и существ тоже в JSON. Все остальные цвета, включая бабушку, небо и кнопки, лежат в одном файле `scripts/theme.gd`.

Новый id улучшения без кода попадёт в лавку, но эффекта не даст. Новый край или новая нечисть подхватываются сразу.

## Как править

Любой из трёх путей пишет в одни и те же JSON.

1. **Файл.** Поменять число и сохранить. Godot подхватит при следующем запуске.
2. **Док редактора.** Плагин «Баланс чердака» включён в проекте. Справа док «Баланс»: разделы, список, поля, «Сохранить». Если дока нет: Проект → Настройки проекта → Плагины → включить «Баланс чердака».
3. **Экран в игре.** На титре «Править данные», в лавке та же кнопка, с клавиатуры `E`. Там же можно стереть правки `user://` и прогресс.

Куда ложится запись:

- Пока проект открыт в редакторе Godot, «Сохранить» пишет в `res://data/`. Так док и плейтест не расходятся.
- В веб-сборке и в экспорте `res://` только для чтения, поэтому правка ложится в `user://` и перекрывает встроенные файлы. «Сбросить правки» возвращает числа из сборки. Прогресс при этом не трогается: он отдельно, в `user://save.json`.

Проверка без окна:

```bash
godot --headless --path throw -s res://scripts/sim.gd
```

Скрипт проверяет пороги краёв, загон, потолок оффлайна, один бросок через экран и редактор чисел. Потом гоняет активного и ленивого игрока и печатает, когда открывается каждый край и когда бестиарий собран. Ненулевой код значит, что правила сломались или активный игрок не собирает коллекцию за шесть часов.

Звуки синтетические. Пересобрать: `python3 throw/tools/make_sfx.py`.

## Веб

Пресет **Web**: `variant/thread_support=false`, `progressive_web_app/ensure_cross_origin_isolation_headers=false`. GitHub Pages такие заголовки не отдаёт.

Локально:

```bash
godot --headless --path throw --import --quit
godot --headless --path throw --export-release "Web" /tmp/throw-web/index.html
python3 -m http.server -d /tmp/throw-web 8766
```

Нужны экспортные шаблоны той же версии. В CI их ставит `.github/workflows/pages.yml`: качает Godot 4.7.2, забирает из архива шаблонов только `web_nothreads_*` и кладёт эту игру в `/throw/`, дверь в `/door/`, а корневые `index.html`, `game.js`, `style.css` и `assets/` копирует как были.

## Android

Пресет **Android** уже в `export_presets.cfg`:

- пакет `com.dmitriigame.throwcollect`;
- имя «Бросай и лови»;
- портрет берётся из настройки проекта `display/window/handheld/orientation = portrait`, её читает экспорт Android;
- архитектура `arm64-v8a`, формат APK, immersive и edge-to-edge.

Сборка APK в CI не включена: для подписи нужен keystore, а для Gradle — Android SDK. Деплой Pages из‑за этого не зависит от Android.

Собрать у себя:

1. Editor → Manage Export Templates, шаблоны 4.7.2.
2. Поставить Android SDK (хватит command-line tools и build-tools) и указать пути в Editor Settings → Export → Android.
3. Создать keystore:

```bash
keytool -genkeypair -v -keystore throw.keystore -alias throwcollect -keyalg RSA -keysize 2048 -validity 10000
```

4. В пресете Android вписать путь к keystore, alias и пароли (release; для отладки Godot может взять debug-keystore).
5. Проект → Экспорт → Android → `throw/build/android/throw.apk`.
6. `adb install -r throw/build/android/throw.apk`.

Если позже понадобится APK из GitHub Actions, в job нужны SDK, шаблон `android_source.zip` и секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Сейчас этого нет специально.
